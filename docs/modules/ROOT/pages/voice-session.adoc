= Voice session

The application exposes a WebSocket voice endpoint at `/ws/voice`. The
session logic is transport-neutral: a `VoiceSession` consumes typed commands
and returns typed events, so the WebSocket carrier can later be replaced (for
example with WebRTC) without changing session behavior.

== Authentication

The connection is accepted without authentication and is authenticated by the
first client message. A `start_session` command carries a OneCX token in the
`apm_principal_token` field; the session authenticates it before doing anything
else:

. The token's signature, issuer, and expiry are verified against the Keycloak
JWKS by the authentication adapter.
. Chat access for `chat_id` is checked with the token propagated to the
chat service.
. The user's existing voice permission is checked.
. The agent configuration for `agent_id` is pinned for the whole session.

Every step fails closed: an invalid or expired token, a chat the user cannot
access, a missing voice permission, or an unpinnable agent configuration closes
or rejects the session with a typed `error` event rather than proceeding.

The legacy query-string form (`?token=...`) is no longer accepted. A
connection that presents a `token` query parameter is closed with code `1008`
before it is accepted.

== Commands

Commands are JSON objects with a `type` field, sent by the client.

[cols="1,3",options="header"]
|===
| `type` | Payload

| `start_session`
| `agent_id` (string), `chat_id` (string), and `apm_principal_token`
(string). Authenticates the token, checks chat access and voice permission,
pins the agent configuration snapshot, discovers MCP tools once, and moves
the session to the listening state. This is the first command the session
accepts.

| `audio`
| `audio` (base64 string) — a finalized chunk of captured microphone audio.

| `stop`
| none — ends the session and returns to typed chat.

| `refresh_token`
| `apm_principal_token` (string). Replaces the session's token with a fresh
one after authentication, so the current session survives a token rotation.
|===

== Events

Events are JSON objects with a `kind` field, emitted by the session.

[cols="1,3",options="header"]
|===
| `kind` | Meaning

| `session_ready` | The session is listening; carries `session_id`, `agent_id`, and `agent_version`.
| `transcript` | Finalized speech recognition; carries `text` and `state`.
| `assistant_text` | Assistant caption; carries `text` and `status`.
| `assistant_audio` | Synthesized speech; carries base64 `audio` and `state` (`COMPLETE` or `FAILED`).
| `turn_complete` | The turn finished; carries the persisted assistant `entry_id`.
| `error` | A typed failure; carries `code` and `message`.
| `session_closed` | The session ended; carries a `reason`.
| `degraded_capability` | An MCP server could not be reached during the once-per-session tool discovery; the session continues without that server's tools.
|===

The `error` event carries one of the following `code` values:

* `authentication_failed` — the token is missing, invalid, or expired.
* `chat_not_accessible` — chat access for `chat_id` was denied.
* `voice_not_permitted` — the user has no voice permission.
* `config_unavailable` — the agent configuration could not be pinned (voice
disabled, conflict, or the agent service unreachable).
* `token_expired` — the session token expired mid-session; the session is
closed.
* `illegal_state` — a command arrived in the wrong state (audio before
`start_session`, a second `start_session`, or a `refresh_token`/audio after
the session closed).

== Behavior

* Starting a session without valid configuration fails closed with an `error`
of code `config_unavailable`; the session stays unstarted.
* Audio before `start_session`, or a second `start_session`, is rejected with
an `error` of code `illegal_state`.
* Only finalized transcripts are persisted. Empty, noise-only input stays
ephemeral and emits no events.
* A completed turn persists one human entry and one assistant entry through the
persistence adapter.
* Speech synthesis failure keeps the assistant text and emits `assistant_audio`
with `state` `FAILED`, so the answer is never discarded.
* MCP tools are discovered once, when the session starts. The authenticated
token is propagated to each MCP server. A server that fails is skipped, and a
`degraded_capability` event is emitted for it; the session continues with the
tools that resolved successfully.
* Only tools whose execution policy resolves to `ALWAYS_ALLOW` are advertised
to the assistant. Tools that resolve to `ALWAYS_ASK` or `DENY` are withheld.
* The agent configuration is pinned once at `start_session` and is not
re-read for the lifetime of the session.
* A `refresh_token` command swaps in a new token after authentication. An
expired token ends the session with an `error` of code `token_expired` and a
`session_closed` event.
