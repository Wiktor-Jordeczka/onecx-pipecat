= Voice session

The application exposes a WebSocket voice endpoint at `/ws/voice`. The
session logic is transport-neutral: a `VoiceSession` consumes typed commands
and returns typed events, so the WebSocket carrier can later be replaced (for
example with WebRTC) without changing session behavior.

== Authentication

The connection is accepted without authentication and is authenticated by the
first client message. A `start_session` command carries a OneCX token in the
`apm_principal_token` field; the session authenticates it before doing anything
else:

. The token's signature, issuer, and expiry are verified against the Keycloak
JWKS by the authentication adapter.
. Chat access for `chat_id` is checked with the token propagated to the
chat service.
. The user's existing voice permission is checked.
. The agent configuration for `agent_id` is pinned for the whole session.

Every step fails closed: an invalid or expired token, a chat the user is
neither the owner of nor a participant in, a missing voice permission, or an
unpinnable agent configuration sends a typed `error` event followed by
`session_closed` (reason `start_failed`), then closes the connection with code
`1008`. A failed start leaves no session state behind and cannot be retried on
the same connection.

The legacy query-string form (`?token=...`) is no longer accepted, and the
endpoint takes no query parameters at all. A connection that presents any
query parameter is closed with code `1008` before it is accepted.

== Commands

Commands are JSON objects with a `type` field, sent by the client.

[cols="1,3",options="header"]
|===
| `type` | Payload

| `start_session`
| `agent_id` (string), `chat_id` (string), and `apm_principal_token`
(string). Authenticates the token, checks chat access and voice permission,
pins the agent configuration snapshot, discovers MCP tools once, and moves
the session to the listening state. This is the first command the session
accepts.

| `audio`
| `audio` (base64 string) — a finalized chunk of captured microphone audio.

| `stop`
| none — ends the session and returns to typed chat.

| `refresh_token`
| `apm_principal_token` (string). Replaces the session's token with a fresh
one after authentication, so the current session survives a token rotation.
|===

== Events

Events are JSON objects with a `kind` field, emitted by the session.

[cols="1,3",options="header"]
|===
| `kind` | Meaning

| `session_ready` | The session is listening; carries `session_id`, `agent_id`, and `schema_version` (the pinned `AgentConfiguration.schemaVersion`).
| `transcript` | Speech recognition; carries `text` and `state` (`PARTIAL` or `FINAL`). Partial transcripts stream to the client and are never persisted; the final transcript is what creates the single durable human entry.
| `assistant_text` | Assistant caption; carries `text` and `status` (`COMPLETED`).
| `assistant_audio` | Synthesized speech; carries base64 `audio` and `state` (`SYNTHESIZING` for each streamed chunk, `FAILED` when synthesis fails).
| `turn_complete` | The turn reached a terminal state; carries the persisted assistant `entry_id`. Sent only after the assistant entry has been persisted.
| `error` | A typed failure; carries `code` and `message`.
| `session_closed` | The session ended; carries a `reason`.
| `degraded_capability` | An MCP server could not be reached during the once-per-session tool discovery; the session continues without that server's tools.
|===

The `error` event carries one of the following `code` values:

* `authentication_failed` — the token is missing, invalid, or expired.
* `chat_not_accessible` — chat access for `chat_id` was denied.
* `voice_not_permitted` — the user has no voice permission.
* `config_unavailable` — the agent configuration could not be pinned (voice
disabled, conflict, or the agent service unreachable).
* `token_expired` — the session token expired mid-session; the session is
closed. Expiry is checked on every command and periodically while idle.
* `principal_mismatch` — a `refresh_token` carried a token for a different
subject or tenant than the user who started the session; the token is not
applied.
* `illegal_state` — a command arrived in the wrong state (audio before
`start_session`, a second `start_session`, or a `refresh_token`/audio after
the session closed).
* `unsupported_language` — the speech provider is `aws` and the pinned language
has no configured Transcribe/Polly profile; no turn is started and no history
is written.
* `stt_failed` — speech transcription failed; the turn ends with no human entry.
* `tts_failed` — speech synthesis failed; the assistant caption is kept and the
assistant entry is still written.
* `persistence_failed` — the durable entry could not be written; no `turn_complete`
is sent and no history is fabricated.
* `turn_failed` — a voice turn raised unexpectedly; the session is left usable so
the next utterance can start a new turn.

== Behavior

* Starting a session without valid configuration fails closed with an `error`
of code `config_unavailable`; the session is closed.
* Audio before `start_session`, or a second `start_session`, is rejected with
an `error` of code `illegal_state`.
* Only the final transcript is persisted. Partial transcripts stream to the
client and are never persisted. Empty, noise-only input stays ephemeral and
emits no events.
* A turn persists at most one human entry and one assistant entry, each written
once in a terminal state through the persistence adapter.
* Speech synthesis failure keeps the assistant text and emits `assistant_audio`
with `state` `FAILED`, so the answer is never discarded.
* MCP tools are discovered once, when the session starts. The authenticated
token is propagated to each MCP server. A server that fails is skipped, and a
`degraded_capability` event is emitted for it; the session continues with the
tools that resolved successfully.
* Only tools whose execution policy resolves to `ALWAYS_ALLOW` are advertised
to the assistant. Tools that resolve to `ALWAYS_ASK` or `DENY` are withheld and
`VoiceSession.invoke_tool` refuses to invoke them. MCP redirects are not
followed, so the user's token is never forwarded to another host.
* The agent configuration is pinned once at `start_session` and is not
re-read for the lifetime of the session.
* A `refresh_token` command swaps in a new token after authentication. The
token must belong to the same subject and tenant as the session's user,
otherwise it is rejected with `principal_mismatch`. An
expired token ends the session with an `error` of code `token_expired` and a
`session_closed` event.

== Turn lifecycle

Each `audio` command drives one voice turn, run as a real Pipecat pipeline of a
speech-recognition (STT) stage and a speech-synthesis (TTS) stage. The turn
streams its output to the client through the transport in order and reaches a
single terminal state:

* The STT stage streams `transcript` events with `state` `PARTIAL` while
recognizing and one with `state` `FINAL` for the finalized transcript. Partials
are never persisted.
* On the final transcript the turn persists the single durable human entry. If
that write fails it emits `persistence_failed` and ends without fabricating the
assistant turn or a completion event.
* It then emits the assistant caption (`assistant_text`, `COMPLETED`) and
streams the assistant audio incrementally, emitting one `assistant_audio`
(`SYNTHESIZING`) per chunk.
* On natural completion the assistant entry is written with status `COMPLETED`,
and `turn_complete` is sent only after that write has succeeded.

== Barge-in

If the user speaks again while the assistant is still playing, the new utterance
barges in on the in-flight turn. Barge-in is delivered through Pipecat's
interruption broadcasting (the non-deprecated `broadcast_interruption`, which
broadcasts an `InterruptionFrame`), so the in-flight TTS output is cancelled and
the interrupted assistant entry is finalized with status `INTERRUPTED` from the
text emitted so far. If nothing had been emitted yet, no assistant entry is
written. The barge-in is final before the new turn begins, so the previous turn's
pipeline and adapter resources are released while the session stays responsive.

== Speech provider and language

The speech provider and its language mapping come from configuration (see
xref:configuration.adoc[Configuration]). When the provider is `aws`, the
language pinned by the agent configuration at `start_session` is resolved to the
deployment's AWS Transcribe language code and Amazon Polly voice. A language
that has no configured profile produces a typed `unsupported_language` error; no
turn is started and nothing is persisted.
